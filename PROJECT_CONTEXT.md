# İTF Geriatri — project context

Updated: 2026-11-20. Keep this file short and update only when project structure or important decisions change.

## Project
- Repository: https://github.com/denizseyithanoglu/itf-geriatri (default branch: `main`)
- Public site: https://denizseyithanoglu.github.io/itf-geriatri/
- Static GitHub Pages website for İstanbul Tıp Fakültesi Geriatri, with Turkish/English content.

## Key locations
- Homepage and public sections: `index.html`, `hastalar.html`, `hekimler.html`, and related root-level HTML pages.
- Online comprehensive geriatric assessment (KGD): `tools/kgd.html`.
- KGD appointment and follow-up forms: `tools/ilk-muayene.*`, `tools/kontrol-takip.*`.
- Kontrol/Takip geriatric screen: six cards per desktop row (responsive), one GYA/EGYA numeric card (`adl` 0–6, `iadl` 0–8), separate chewing (`chew`) and swallowing (`swallow`) questions, "Uyku Bozukluğu" label; typing an explicit PLAN number must not auto-prefix it again.
- Kontrol/Takip Post-it: draggable via `#scratchDragHandle`, viewport-bounded, position in tab-scoped sessionStorage. Scratch notes enter PLAN **only** via `PLAN'a Aktar`, not on scroll/focus/blur/show/copy/print; scratch draft is still saved locally.
- Report/output logic: `tools/form-output.js`.
- Print/PDF names: `tarih_isimsoyisim_formadı`, generated by `FormOutput.filename(date,name,form)`; KGD and standalone KGD/Ölçümler use Özet/Detaylı suffixes, İlk Muayene and Kontrol/Takip select their respective report modes. Detailed KGD and other clinical print layouts use print-only compact CSS; do not compress clinical data or alter score calculations.
- KGD full-summary print layout: `compactKGDStep()` in `tools/kgd.html`; Sosyal Öykü uses 3 ordered compact rows, and Özgeçmiş lists positive diagnoses, fractures, medications beside family history, and habits under family history.
- Full KGD short report groups MNA-SF, combined /30 MNA-LF, function/QoL, frailty, cognition, and mood as one `KGD Tarama Anketi` section (one line per domain). Physical Performance remains separate: units are shown, `%` is directly prefixed, probable sarcopenia follows SPPB, and confirmed/severe results are grouped by SMM index. Detailed reports and saved clinical field keys remain unchanged.
- Full KGD detailed print: `kgdDetailedPrintStep()` and `kgdDetailedBlock()` group related fields into compact 2–3-column rows; merge social, fall, pain/sleep/voiding, MNA-LF, and EQ-5D duplicate headings while retaining distinct answers, itemized scale responses and notes. Screen layout, scoring and keys stay unchanged.
- Data export: `tools/kgd-export/`.
- Physical performance: `tools/fiziksel-performans.html`, `scripts/build-physical-performance.py`.
- Patient self-assessment: `tools/self-assessment.html`.
- Nutrition tool: `tools/nutrition.html`.
- Branding assets: `assets/`.

## Checks
- Tests: `tests/form-output.cjs`, `tests/kgd-export.cjs`, `tests/physical-report-groups.cjs`.
- GitHub Actions: `.github/workflows/kgd-validation.yml` checks KGD JavaScript and printing behavior.
- When editing relevant features, run their focused tests and the KGD validation checks where applicable.

## Change discipline
- Follow `AGENTS.md`.
- Preserve existing forms, scoring, report formats, data export, and other site features unless explicitly asked to change them.
- Inspect only task-relevant files; avoid broad repository scans and unrelated cleanup.
- Never add identifiable patient data or secrets to tracked files.
